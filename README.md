# Ученики и просмотры уроков ЦОК

Дашборд учеников и просмотров уроков ЦОК в «Моей школе»: по дням, по дням недели, по регионам, школам и курсам.

- `index.html` — сайт (GitHub Pages). Цифры берёт из `data.json`, сентябрь — из `frozen.json`, названия курсов и уроков — из `catalog.json`.
- `apps-script/Code.gs` — скрипт Google Apps Script: читает выгрузки Metabase из папки на Google Диске и кладёт сводные цифры в `data.json`.

Обновление данных: положить новую выгрузку (xlsx) в папку на Google Диске.

## Что как считается (с 16.11.2026)

- **Ученик** — user_id «Моей школы» с указанным регионом. Токен — доступ ученика к платформе (один на ученика). Появляется в момент входа (`created_at`).
- **Просмотр** — пара «ученик — урок». Время — `timeStart` (с какого-то момента это вход в практическую часть урока), а если его нет — `created_at` (так бывает только у урока, с которого ученик пришёл). Повторное открытие того же урока в выгрузке не видно.
- **Повторный просмотр** — второй, третий и следующие уроки одного ученика (по времени просмотра).
- **Учителя** — строки с токеном, но без региона: не учитываются.
- Строки выгрузки без токена (активность на Фоксфорде без связи с «Моей школой») пропускаются.
- Данные до 6 октября — из отчёта «Моей школы» (`frozen.json`, только просмотры) и не меняются.

Выгрузка с 16.11 «склеенная»: к каждому токену приклеены все уроки ученика, поэтому файл большой (≈18 МБ, ≈150 МБ после распаковки). Скрипт распаковывает такие файлы сам, кусками.

## Биллинг

Вкладка «Биллинг» закрыта паролем: цифры биллинга в `data.json` не попадают, сайт получает их POST-запросом у скрипта Google после проверки пароля. Пароль задаётся в свойствах скрипта под именем `BILLING_PASSWORD`; после изменения кода скрипта нужно выпустить новую версию развертывания (ссылка не меняется).
